# Implementation

Context is a Rust library and CLI. The CLI has no Node runtime or npm dependencies.

## Indexing

`indexer.rs` traverses directories with the ignore crate, applies file/language limits and compares size and nanosecond modification time against the existing index. Eligible updates are read once and hashed with BLAKE3. `source.rs` shares traversal policy with framework discovery and isolated evaluation. Without `.ctxignore`, root `.gitignore` negations explicitly naming a default dependency directory can identify first-party sources there. Broad negations do not opt dependencies in. Positive exclusions inside those trees still apply, and initialization carries these explicit rules into new `.ctxignore` defaults. Existing custom exclusions remain authoritative. Equal hashes update metadata without reparsing.

Rayon workers reuse Tree-sitter parser instances within bounded batches. The batch size bounds retained source bytes to approximately 64 MiB before derived parser/search data, unless the configured individual file limit itself is larger. Metadata and index structures still grow with repository size.

`parser.rs` extracts real declarations and source ranges for TypeScript, JavaScript, PHP, Python, Go, Rust, Ruby and Java. Other UTF-8 files contribute searchable text and references. Named test functions and annotations, and supported literal-title callbacks in Pest and JavaScript/TypeScript test APIs, carry `isTestCase` metadata; callback registrations use kind `test`, while named functions keep their original declaration kind. Callback ranges contain the whole registration and its assertions. Known imports, CommonJS bindings and unshadowed globals in test paths identify supported APIs; comments, dynamic titles, unknown imports and detected parameter/local replacements do not create declarations. Parsing recovers useful declarations from incomplete code; it does not perform type checking or prove runtime dependency relationships.

`database.rs` consumes parsed batches lazily inside a single SQLite transaction. Statements are reused. Deleted and newly excluded files lose their metadata, symbols, import requests, references and full-text entries. Import requests are stored separately from resolved edges, so newly created targets become connected even when the importing source did not change. Schema 10 rebuilds the disposable index to persist named test declarations, literal callback test titles and their structural ranges alongside syntactic test roles, lexical content and dependency kinds. Generated/minified classification remains cached across metadata-only updates and is recomputed in the existing read pass when sources change.

`project.rs` builds a serializable scoped map of TypeScript configs, local package exports, Composer namespaces and Rust library roots. Its fingerprint invalidates resolved edges after config changes, without reparsing unchanged sources. Missing inherited TypeScript configs, including preset packages and generated local files, do not block indexing an unbuilt checkout: local options still apply, and unresolved path/reference pairs appear in index JSON and evaluation reports. Invalid existing configurations, inheritance cycles and paths outside the root still fail. When a preset becomes available, the changed map fingerprint rebuilds imports without requiring source changes. Metadata discovery occurs before language filtering. Explicit framework string references are captured once during parsing and resolved against indexed resources. Neither application code nor package build scripts are executed.

Literal Inertia page references connect backend controllers/providers to indexed frontend page files in the same Composer scope. This lets login pages lead back to authentication setup without relying on a provider filename appearing in the task.

Framework class and blueprint targets use a filename lookup prepared once per graph rebuild, avoiding a full repository scan for every static reference. That derived lookup is excluded from the configuration fingerprint. Java import resolution likewise builds filename/package buckets once per graph rebuild, rather than scanning the repository for each import. It resolves local classes, enclosing sources for nested/static members and direct-package wildcards across arbitrary source roots; missing external imports do not trigger full-file scans.

SQLite FTS5 stores raw text plus split identifiers in a literal column, and lexical stems in a separate column. Corpus normalization never introduces translations or synonyms. Search groups query terms by origin and weight, restricting literal matches to the literal column. Literal terms take priority when the full-text query reaches its term limit. FTS row IDs follow file row IDs, so deleting or replacing one document avoids scanning full-text paths. Import requests have a source-path index. Rejected binary/invalid UTF-8 files retain only metadata, avoiding repeated reads until they change. The index schema is versioned and disposable.

## Task analysis

`resolver.rs` splits identifiers and filters stopwords. `terms.rs` retains literal query terms with weight 1, adds English stems with weight 0.75, and attaches lower-confidence translations and one-hop synonyms only to the query. Each query term records its origin, original word and weight. Ambiguous Italian stems that are also unchanged English words, such as `access`, receive a weaker translation weight. Duplicate translation stems preserve every target. Task analysis also adds explicit paths, symbols, stacktrace locations, Git changes, domains and a change type.

Natural-language token matches are weak search evidence. Only explicit code syntax, CLI symbol hints and recognizable mixed-case/snake-case identifiers reserve symbol slots. Uppercase prose acronyms do not automatically become code references. `frameworks.rs` discovers nested manifest scopes and generates anchored framework ignore rules. The index persists these scopes even when manifest languages are excluded, and the indexed resolver reuses that snapshot.

Confidence scores are heuristic signal summaries, not calibrated probabilities. Timestamp filtering understands UTC log timestamps; logs without timestamps cannot be reliably filtered by age.

## Discovery and ranking

`discovery.rs` loads index metadata once per discovery pass and builds symbol, entity and adjacency maps. It combines exact hints, path terms, full-text content, import traversal, indexed references, related tests/configuration and Node.js/Laravel/Statamic relationships.

Explicit hints reserve slots within the file limit. Path and symbol evidence distinguish literal matches, stems, translations and synonyms, with document frequency reducing ubiquitous terms. Domain paths can recover candidates without direct query-word matches. Domain boosts respect task weights and package boundaries. Git activity is a small secondary signal. Generated/minified assets receive a visible penalty unless explicitly hinted and do not seed ordinary graph expansion.

`graph.rs` traverses directed, typed dependencies. Outgoing imports have stronger evidence than incoming consumers; literal view/Inertia links support reverse traversal back to the backend. Fan-in and fan-out reduce hub influence, and depth, seed and visited-node limits bound expansion. Generic shared-symbol references and filename associations provide weak, non-recursive evidence within package scopes.

`behavior.rs` associates strong implementation candidates with tests through direct imports or normalized source/test counterparts within package scopes. Ambiguous generic basenames do not create counterparts, import fan-out damps broad test hubs, and each implementation contributes at most three test links. Evidence records the implementation and relationship. These links can add marginal behavior coverage once their implementation is selected. Direct test terms, or inherited source terms when absent, identify query facets within a package scope. Additional tests for already covered facets are skipped unless they add other direct query, scope or dependency evidence; testing focus lifts that rule. The general test ceiling remains in force. Test-link score additions are bounded below the implementation score for general tasks.

`runtime.rs` extracts literal configuration keys and known authentication/session calls from PHP call nodes. Config keys resolve to existing `config/<section>.php` files. Fortify, authentication and session calls connect their runtime configuration and `bootstrap/app.php` within the nearest Composer scope. Comments and quoted examples do not create these runtime edges. These scoped conventions require source evidence, without forcing runtime files merely because a task contains “login”.

`selection.rs` treats `max-files` as a ceiling. It selects candidates by relevance and the additional query, package, file-role and dependency evidence they contribute. It stops when remaining evidence has insufficient marginal value. Distinct dependencies and runtime configurations can add useful context even without task-word matches. Explicit package intent restricts graph seeds and reduces the utility of other scopes; language/framework names and nested test-fixture scopes do not imply package intent; ambiguous requests can retain multiple implementations. Tests, including `e2e` helpers, have a one-fifth ceiling for general tasks, lifted for testing tasks. Explicit hints bypass this test ceiling. Final results use descending relevance and path ties.

Leading declaration-name query matches add `test_intent` evidence when the same query concept appears in implementation paths or declarations. Qualifying clauses, late incidental mentions and titles covering only a small fraction of implementation-supported task concepts are discounted. Callback descriptions do not contribute ordinary identifier evidence or graph seed strength. Their behavior coverage is separate from implementation coverage, scoped by package and original query concept. Equivalent tests share that feature. Test intent does not consume implementation query coverage or raise the relevance admission floor. Where an implementation relationship already exists, the declaration bonus respects its pre-domain score ceiling and behavior novelty waits for the implementation. The bonus is applied after seed selection so it does not recursively amplify discovery. Test support files in conventional helper/support/fixture paths or named environment/setup utilities do not propagate reverse dependencies into other tests for general tasks, unless they contain actual test declarations or are explicitly reserved. Testing focus retains the broader traversal.

Ranking remains heuristic. Framework links and syntactic imports are useful context signals, not a complete semantic call graph.

Each ranking addition and multiplier records a numerical contribution. Candidate evidence also records lexical origin or dependency source, relation kind and hop count. `query.rs` shares discovery with search, explanations and MCP. Explanations rank all scored candidates independently of marginal selection and distinguish omitted candidates, file limits and explicit exclusions without reserving a selected slot for the queried file.

## Git

`git.rs` invokes Git directly without a shell. Revision arguments are validated before diff operations. Diff collection uses explicit prefixes and disables external diff tools, so user Git display configuration does not change parsing. History is collected in one batched log operation and cached by HEAD and the indexed path set. It covers the latest 500 commits.

## Packs

In dedicated test files with a clearly matched case, `test_context.rs` refines structural proposals before allocation. Unmatched sibling cases and unreferenced named helpers are excluded from every proposal, including enclosing classes and text windows. The matched declarations retain their assertions. Context includes imports, class headers, scoped lifecycle hooks, referenced bindings and transitive file-local helpers. Referenced fixture classes retain shared declarations, and local base classes contribute setup while their unrelated tests remain masked. The strongest matched case precedes required setup/helpers, which precede additional cases and optional container context under the same file/test/token ceilings. Dynamic dispatch and inherited behavior remain conservative syntax analysis. Explicit file or non-case symbol requests, testing focus, ambiguous matches and parse errors retain broader excerpts. Error/diff locations and explicit case names keep the corresponding cases. These are bounded syntax heuristics, not full dependency or fixture resolution, and normal token/line limits still apply.

`snippets.rs` scores structural declarations, weighted query matches, error anchors and all changed regions. Literal query evidence outweighs translation and synonym matches when selecting source ranges. Each original query concept contributes its strongest matching origin on a source line. Structural scoring favors declaration names and caps accumulated body evidence at eight points; comment-only matches receive less weight in test/configuration files and mixed implementation/test files. Ordinary implementation files retain the reference scoring precision and text-window ordering. A file-local rarity scorer and universal production priority were rejected after the first unseen-repository evaluation lost essential code. Production priority applies only in files mixing implementation and embedded tests. Parsers persist test roles from conventional paths, Rust test attributes/modules, Java test annotations and Python test names; relevant production declarations take precedence over embedded tests unless a test or source location is explicit. Oversized functions can contribute up to three separated regions when each adds distinct original query concepts. Repeated concepts and composite classes retain a contiguous context window. Configuration excerpts also propose active assignment/key lines, avoiding budgets spent on comment headers alone. It prefers complete declarations, adds import context, merges overlapping ranges and enforces a total line limit per file. Progressive rounds grow relevance-weighted allowances, granting one section per source per round. Multiple readable sources each have a half-allowance ceiling after header costs; a single source can use all remaining tokens. Oversized units are clipped around relevant lines with UTF-8-safe line boundaries. A line exceeding its source ceiling cannot consume another source's allocation and can produce an `oversized_line` omission. Multiple excerpts have distinct range-qualified filenames.

`tokens.rs` caches embedded BPE encoders lazily. `approx` preserves the original byte estimate; selectable `cl100k_base` and `o200k_base` count the complete prompt. Every proposed allocation is checked against the final assembled text so boundaries between Markdown sections cannot exceed the token budget. An accepted allocation must add source lines; metadata-only changes between overlapping clipped declarations cannot keep the allocation loop running. No network tokenizer download is needed. For general tasks, unreserved test files share an initial one-fifth excerpt allowance while implementation grows; after implementation cannot grow further, tests may use unused capacity. Explicit test references and testing focus bypass this quota.

`pack.rs` preserves existing reports and manifest fields, adding source hashes, multiple ranges, effective options/configuration, selected relationships and parent/update metadata. Incremental composition verifies selected source hashes, sends changed/new excerpts and explicitly invalidates removed context and stale relationships. Unchanged ranges refer to the retained parent chain. Old manifests deserialize with defaults and get a full first refresh when source hashes or query provenance are absent. Changes in weighted query evidence also refresh retained excerpts. Manifests record `excerptStrategyVersion` (currently 3); older or different policies force one full refresh even when source hashes are unchanged.

All reports and a tar.gz archive are written to an owned staging directory. A successful rename makes the completed pack visible; failures remove the staging directory. Archive entry order, permissions and timestamps are normalized. The manifest and pack slug contain invocation timestamps.

`main.rs` provides Clap commands, JSON output, task completion through rustyline, and platform-native opening. Public Rust modules expose the same processing stages for integrations.

`mcp.rs` wraps these APIs with the official Rust MCP SDK over stdio. It fixes the project root at startup, serializes index/pack operations and exposes tools plus saved-prompt resources. `evaluation.rs` runs labeled cases in isolated temporary copies or pinned Git archives and fingerprints their datasets and indexed sources. Its annotation, literal-baseline and scoring modules distinguish selected files, actual required/supporting code, unknown relevance and omission causes, with grouped quality and cost reports. `scripts/corpus.py` verifies pinned public archives and source labels, bounds isolated measurement processes, retains failures and records process timing/memory across budgets. See the integration and evaluation guides for their contracts.
